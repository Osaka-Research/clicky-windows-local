# Building the Auto installer

Two steps: publish a self-contained build, then compile it into a single
installer .exe with [Inno Setup](https://jrsoftware.org/isinfo.php).

## 1. Publish

```
dotnet publish AutoWindows.csproj -c Release -r win-x64 --self-contained true -o publish\win-x64
```

Self-contained, not framework-dependent -- bundles the .NET 8 runtime so
whoever runs the installer doesn't need it preinstalled. This is the folder
`Auto.iss` packages (`PublishDir` at the top of the script).

## 2. Compile the installer

Needs Inno Setup 6 installed (`winget install JRSoftware.InnoSetup`, or
download from the link above). Then:

```
iscc installer\Auto.iss
```

Output: `installer-output\AutoSetup.exe` -- a single-file installer, per-user
install (no admin/UAC prompt), Start Menu shortcut, optional desktop shortcut,
proper uninstaller registered in Add/Remove Programs.

## Branding assets

`assets/wizard-banner.bmp`, `assets/wizard-small.bmp`, `assets/setup.ico` --
the dark-ink/periwinkle-glow dot used throughout the app (reply panel, tray,
homepage). Generated by `gen_installer_assets.py` (needs Python + Pillow):

```
python3 installer/gen_installer_assets.py installer/assets
```

Re-run after changing the accent color or dimensions; the script is the
source of truth, not the checked-in .bmp/.ico files.

## What's NOT handled yet

- **Code signing.** The output .exe is unsigned -- Windows SmartScreen will
  show an "unrecognized publisher" warning on first run until this has been
  downloaded enough times to build reputation, or until it's signed with an
  actual code-signing certificate (a paid step, out of scope here).
- **Auto-update.** No update-check/self-update mechanism -- a new version
  means building and distributing a new installer, which a returning user
  runs over their existing install (Inno Setup handles that as an upgrade
  in place, since AppId stays constant across versions).
